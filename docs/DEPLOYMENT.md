# Deployment

**None of this has been executed.** The steps follow each provider's documented flow. Treat
the first deployment as a test and expect adjustments. Local setup is in the README.

Layout: Supabase (PostgreSQL) ← Render (backend container) ← Vercel (static frontend that
rewrites `/api/*` to Render).

## 1. Put the code in a Git repository

```bash
cd CareBridge-AI
git init && git add . && git commit -m "CareBridge AI 0.1.0"
```

Create an empty repository on GitHub and push. Check that no `.env` file is included.

## 2. Database: Supabase

1. Create a project. Choose a region near your users (Mumbai, `ap-south-1`).
2. Project Settings → Database → Connection string. Copy the **Session pooler** URI
   (`postgresql://postgres.<ref>:<password>@...pooler.supabase.com:5432/postgres`).
   The direct connection may be IPv6-only, which Render's free plan may not reach.
3. Keep this URI private. The backend accepts `postgresql://` and converts it to the psycopg
   driver form itself.
4. From your machine, apply the schema and (for a demo) the seed data:
   ```bash
   cd backend && source .venv/bin/activate
   export DATABASE_URL='<the URI>'  JWT_SECRET_KEY='<any 32+ characters for this shell>'
   alembic upgrade head
   SEED_PASSWORD='<choose your own>' python -m scripts.seed
   ```
5. In the Supabase SQL editor, run the contents of `backend/scripts/supabase_enable_rls.sql`.

## 3. Backend: Render

1. New → Blueprint, pick the repository. `render.yaml` defines one free Docker web service
   rooted at `backend/`.
2. Enter the values marked "sync: false": `DATABASE_URL` (from step 2) and `CORS_ORIGINS`
   (your Vercel URL, for example `https://your-app.vercel.app`). `JWT_SECRET_KEY` is
   generated by Render. Leave the provider keys empty unless you use them.
3. Deploy. The container runs `alembic upgrade head` and then starts the server.
4. Check `https://<service>.onrender.com/api/v1/health/ready`.

## 4. Frontend: Vercel

1. In `frontend/vercel.json`, replace `REPLACE-WITH-YOUR-BACKEND.onrender.com` with your
   Render host name. Commit and push.
2. Import the repository in Vercel. Set **Root Directory** to `frontend`. Framework: Vite.
3. Deploy, open the site, sign in with a seeded account.

Because the browser only ever calls its own origin, the refresh cookie is first-party. If
you serve the frontend from a different host than the one doing the rewrite, sign-in renewal
will fail.

## 5. Optional providers

Set in the Render dashboard, then redeploy:

- Gemini: `LLM_PROVIDER=gemini`, `GEMINI_API_KEY`. Confirm `GEMINI_MODEL` names a model that
  exists on your key's free tier.
- Azure Speech: create a Speech resource on the **F0** tier, then `SPEECH_PROVIDER=azure`,
  `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION` (for example `centralindia`).

## 6. After deploying

- `GET /api/v1/health/ready` shows database and provider status.
- First request after idle takes about a minute on Render's free plan; the UI shows a
  "service may be starting" message and a retry button.
- Supabase pauses idle free projects; unpause from its dashboard.
- Run one worker only. The rate limiter and background jobs assume a single process.

## Rollback

Render keeps previous deploys: use "Rollback" on the service. Database changes are not rolled
back automatically; `alembic downgrade` applies only to revisions that define a downgrade.
